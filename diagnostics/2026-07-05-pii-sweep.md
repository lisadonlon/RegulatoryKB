### F-01 · Operational email addresses in `config/config.yaml` · MEDIUM (Unresolved — 2nd occurrence)

**Pattern:** `intelligence.email.sender` and `intelligence.email.recipients` fields contain real organisational email addresses belonging to `*@donlonlsc.com` and `*@vertigenius.com`.

**Risk:** Anyone with read access to the repository (or its history) can harvest operational contact addresses. If the repo is ever made public or cloned outside the intended audience, these become externally visible. Config with real credentials-adjacent data should live in `.env` / environment variables, not committed YAML.

**Status:** Flagged in 2026-06-07 sweep (P2) and 2026-06-14 sweep. Not yet remediated.

**Recommended action:** Move `sender` / `recipients` to environment variables (`SMTP_SENDER`, `SMTP_RECIPIENTS`) and replace the committed values in `config.yaml` with clearly-synthetic placeholders (e.g. `*@example.com`).

### F-02 · Hardcoded domain fallback in `emailer.py` · MEDIUM (Unresolved — 2nd occurrence)

**Pattern:** `config.get("intelligence.email.sender", "regulatory@vertigenius.com")` — a real company-domain address is the hard-coded fallback in production code.

**File:** `scripts/regkb/intelligence/emailer.py`

**Risk:** If the config key is missing or mis-spelled, the emailer silently uses a real domain address as sender, potentially exposing the domain in mail headers sent to arbitrary recipients. Also leaks the domain in source control.

**Status:** Flagged in 2026-06-14 sweep (MEDIUM). Not yet remediated.

**Recommended action:** Replace the fallback with an empty string `""` or a synthetic value such as `"regulatory@example.com"`. Raise an explicit `ConfigError` if the sender is empty at startup.
