## Finding Details

### F-01 · config/config.yaml · Operator email in committed config · MEDIUM

**Context:** The runtime config file contains the operator's actual email addresses as SMTP sender and digest recipient values (both on `*@donlonlsc.com` and `*@vertigenius.com` domains). The file is committed to the repository.

**Risk:** Low-to-medium. The email addresses are the operator's own business contacts, expected in a personal/team knowledge base. However, committing runtime config with real email addresses to a repo means any future collaborator or public mirror would expose them.

**Recommendation:** Move operator-specific email configuration to `.env` (already `.gitignore`d) and replace `config.yaml` values with `${ENV_VAR}` references or empty-string defaults. Mark `config/config.yaml` as a template file.

### F-02 · scripts/regkb/intelligence/emailer.py · Hardcoded domain default · MEDIUM ⚠️ CARRY-OVER

**Context:** A `config.get(…, "regulatory@*@vertigenius.com")` fallback default embeds a real business domain as a code-level default.

**Risk:** Medium. If the config key is missing, the real domain silently becomes the sender address. Flagged in the 2026-06-14 sweep — **still unresolved.**
