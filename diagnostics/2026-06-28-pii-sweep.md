## Findings Detail

### F-01 · MEDIUM — Business email addresses hardcoded in `config/config.yaml`

`config/config.yaml` contains real `@vertigenius.com` and `@donlonlsc.com`
addresses as default SMTP sender and recipient values under
`intelligence.email.sender` / `intelligence.email.recipients`.

**Risk:** Config file is version-controlled. Committing real business email
addresses exposes them in git history and to anyone with repo access.

**Recommended action:** Replace hardcoded values with environment variable
references, e.g. `${SMTP_SENDER}` / `${SMTP_RECIPIENTS}`, loaded via the
existing `.env` pattern. Document required env vars in `README.md`.

---

### F-02 · LOW — `@vertigenius.com` fallback default in `emailer.py`

`scripts/regkb/intelligence/emailer.py` contains a hardcoded
`*@vertigenius.com` address as a code-level fallback default (not loaded
from config or environment).

**Risk:** Low — no credential attached, but commits PII to source history.

**Recommended action:** Remove the hardcoded fallback; require the address to
be supplied via config/env, raising a clear error if absent.

---

### F-03 · INFORMATIONAL — `@gmail.com` placeholder addresses in setup docs

`README.md`, `scripts/regkb/commands/intel.py`, and
`scripts/regkb/intelligence/scheduler.py` all use `your-email@gmail.com` /
`you@gmail.com` as illustrative placeholders in setup instructions and
generated batch-script comments.

**Risk:** None — these are not real addresses. No action required.

---

### F-04 · INFORMATIONAL — `@test.com` in test fixtures

`tests/test_web_search_resolver.py` uses `*@test.com` addresses as unit-test
data. Benign by design.
